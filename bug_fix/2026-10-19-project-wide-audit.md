## 검사 결과

- 웹: TypeScript 검사와 Next.js 운영 빌드 통과. 전체 ESLint는 기존 설정에서 오류 154건·경고 47건, Next.js ESLint 설정 업데이트 후 오류 194건·경고 50건으로 실패했다. 최신 규칙 기준 `no-explicit-any` 124건, effect 안의 상태 변경 53건이다. 규칙 변경으로 증가한 수치가 새 기능 결함 개수를 뜻하지 않는다.
- 이 작업 환경의 Node `22.12.0`은 `@sparticuz/chromium@149`가 요구하는 `22.17.0`보다 낮다. 웹 빌드는 통과했지만 자동 EduSet 로그인 경로를 이 Node 버전에서 실행 검증하지 않았다.
- 행사 기능: JavaScript helper 테스트 통과. 행사 SQL은 PostgreSQL 테스트 스크립트가 있으나 작업 환경에 Docker/Podman과 로컬 PostgreSQL 서버가 없어 실행하지 못했다. SQL의 운영 적용 상태도 확인하지 못했다.
- 데몬: Python 단위 테스트 7건 통과, Python 구문 검사 통과. 새 재생성·교내 바인딩·접두어 충돌 테스트는 Docker 호출을 모의했다. 실제 Docker 교체 리허설은 하지 않았다.
- SSH 게이트웨이: Go 테스트·race 검사·vet 통과. 교내 Wi-Fi에서 새 LAN 리스너의 TCP·호스트 키·미등록 키 거절을 확인했지만 예약 GPU 로그인은 아직 검증되지 않았다.
- 자료 공유: Python 구문 검사 통과. 이 작업 환경에는 FastAPI 패키지가 없어 HTTP 통합 테스트를 실행하지 못했다.
- 운영: 서버의 GPU 1~4, 공용 SSH·교내 SSH 게이트웨이, 데몬은 실행 중이었다. GPU Jupyter 포트 8001~8004는 `0.0.0.0`과 IPv6 모든 주소에 게시돼 있다. 접근 통제는 Jupyter 비밀번호와 실제 네트워크 정책에 의존한다. 이번 점검에서 외부 접근 가능 여부는 시험하지 않았다.

## 운영 반영 전에 필요한 것

1. CPU 접두어 고유 인덱스 SQL을 운영 Supabase에 적용한다. 충돌 행이 있으면 인덱스가 오류를 내며 중단하므로 먼저 현황을 확인한다. 현재 조회 결과는 CPU 프로젝트 0건이었다.
2. 데몬 변경은 실제 Docker 시험 환경에서 성공·실패·복구 경로를 연습한 뒤, 실행 중인 GPU 작업이 없거나 이용자에게 안내한 시간에 서버에 배포한다. 이 점검에서는 운영 데몬을 재시작하지 않았다.
3. 학교 CPU 프로젝트의 실제 대상 네트워크 대역과 Docker 방화벽 체인을 서버 관리 권한으로 확인한다. 교내 NIC 바인딩만으로 모든 라우팅 정책을 증명할 수 없다.
4. Flutter SDK가 있는 환경에서 앱 분석·빌드를 실행하고, 행사 SQL 테스트를 PostgreSQL 환경에서 실행한다.

참고: [Docker와 UFW](https://docs.docker.com/engine/network/packet-filtering-firewalls/#docker-and-ufw), [Docker 포트 게시](https://docs.docker.com/engine/network/port-publishing/), [Docker create](https://docs.docker.com/reference/cli/docker/container/create/).
